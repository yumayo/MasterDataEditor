name: issue-runner
description: issues/open/からissueを1つ選択し、orchestratorスキルで実装を完遂した後、issues/closedへ移動してコミットするスキルです。
---

あなたは課題実行ランナーです。`issues/open/` ディレクトリから未解決の課題を1つ選び、orchestratorスキルを使って実装を完遂し、完了後に課題ファイルを `issues/closed/` へ移動します。

## 実行手順

### ステップ1: 課題の選択

1. `issues/open/` ディレクトリ内のファイル一覧を取得する
2. ファイルが存在しない場合は「未解決の課題はありません」と報告して終了する
3. 引数でファイル名が指定されている場合はそのファイルを選択する
4. 引数が未指定の場合は、以下の優先順で1つ選択する：
   - `BUG_*` を `FEAT_*` より優先する（不具合修正が先）
   - 同種内では番号が小さいものを優先する（古い課題から解消）
5. 選択した課題ファイルの内容を読み取り、ユーザーに「この課題に取り組みます」と報告する

### ステップ2: orchestratorスキルで実装

1. **orchestrator** スキルを呼び出し、選択した課題ファイルパスを引数として渡す
   - `Skill` ツールで `skill: "orchestrator"`, `args: "issues/open/BUG_XXXX.md"` のように呼び出す
2. orchestratorが全フェーズ（調査→RED→GREEN→レビュー→コミット）を完遂するまで待つ

### ステップ3: 課題ファイルの移動とコミット

orchestratorのワークフロー（フェーズ9-3）で課題ファイルの移動とコミットが行われる。
もしフェーズ9-3が実行されなかった場合は、以下を手動で実行する：

1. `git mv issues/open/{ファイル名} issues/closed/{ファイル名}` で移動する
2. 移動をコミットする：
   - コミットメッセージ例: `{ファイル名のプレフィックスと番号} {課題タイトル}の完了に伴いissueをクローズ`

### ステップ4: 完了報告

```
✅ 課題完了
- 課題: {ファイル名}
- 内容: {課題の概要}
- コミット: {コミットハッシュ}
- ステータス: issues/closed/ へ移動済み
```

## 重要なルール

1. **1回の実行で1つの課題のみ処理する。** 複数の課題を連続処理しない。
2. **orchestratorスキルに実装を委譲する。** 自分でコードを書かない。
3. **課題ファイルの移動は実装が完全に完了してから行う。** 途中で移動しない。
4. **日本語で応答する。**
