# ISSUE_0118 データ型別の入力コントロールを追加する

## 概要

スキーマの列型（int, float, double, bool, string 等）に応じて、セル編集時に専用の入力コントロールを表示する。現状はすべての型で汎用テキストフィールド（GridTextField）が使われているが、型に特化したUIを提供することで入力ミスを防ぎ、編集効率を向上させる。

## 背景

現状のセル編集はすべてテキスト入力であり、以下の問題が発生している:

- **bool列**: `true` / `false` を手入力する必要があり、typo（`ture`, `flase`）が頻発する
- **int列**: 小数点や文字列を入力してもバリデーションエラーになるまで気づけない
- **日付列**: フォーマット不統一（`2026/03/28` vs `2026-03-28`）が起きやすい
- **float/double列**: 指数表記（`1e5`）の入力可否が直感的でない

型に応じた専用UIがあれば、入力時点で不正な値を排除でき、バリデーションエラーの発生を未然に防げる。

## 要件

### bool型: チェックボックス

- セルクリックでチェックボックスのON/OFFを切り替える（テキストフィールドは表示しない）
- 値は `true` / `false` の文字列としてセルに格納する
- セル表示はチェックマークアイコン（ON時）または空（OFF時）
- キーボード操作: Space キーでトグル
- Undo/Redo に対応する

### int型: 数値入力フィールド

- テキストフィールドに `inputmode="numeric"` 相当の制約を適用する
- 数字、`+`、`-` 以外の文字入力を抑制する（入力イベントで即座にフィルタ）
- 上下矢印キーでインクリメント/デクリメント（ステップ1）
- 不正な値を確定しようとした場合、セルをエラー色で強調して確定を拒否する

### float / double型: 小数入力フィールド

- 数字、`+`、`-`、`.`、`e`、`E` 以外の文字入力を抑制する
- 上下矢印キーでインクリメント/デクリメント（ステップは整数部を基準）
- 指数表記（`1.5e3`）を許容する

### date / datetime型（将来のスキーマ拡張用）

- スキーマに `date` / `datetime` 型が追加された場合に備えた拡張ポイントを設ける
- date型: カレンダーピッカーを表示し、選択した日付をフォーマット文字列でセルに格納する
- datetime型: 日付ピッカー + 時刻入力の組み合わせ
- フォーマットはスキーマまたはプロジェクト設定で指定可能にする（例: `yyyy-MM-dd`）
- 現時点では設計方針のみ記載し、date型がスキーマに追加されたタイミングで実装する

### 入力コントロールの選択ロジック

- FK参照列 → 既存の GridDropdownInput を使用する（変更なし）
- bool型 → チェックボックスコントロール
- int型 → 数値フィルタ付きテキストフィールド
- float / double型 → 小数フィルタ付きテキストフィールド
- string型 → 既存の GridTextField をそのまま使用する（変更なし）
- 未知の型 → string型と同じ扱い（汎用テキストフィールド）

### セル表示の型別レンダリング

- bool型: チェックマークSVG
- int / float / double型: 右寄せで表示する（数値の視認性向上）
- string型: 左寄せで表示する（変更なし）

### Undo/Redo対応

- すべての型別入力操作は既存のCommandパターンを通じてUndo/Redoに対応する
- チェックボックスのトグルもセル値変更コマンドとして履歴に記録する

## 期待される動作

1. bool列のセルをクリックすると、チェックマークがトグルされる（true ↔ false）
2. int列のセルを編集開始すると、数字のみ入力可能なフィールドが表示される
3. int列で上下矢印キーを押すと、値がインクリメント/デクリメントされる
4. float列で `abc` のような不正な文字を入力しようとすると、フィルタされて入力できない
5. 数値列のセル表示が右寄せになっている
6. すべての操作が Ctrl+Z / Ctrl+Y で取り消し・やり直しできる
