# ISSUE_0134 ソートとフィルターの状態をスキーマに永続化する

## 概要

列のソート状態（ソートキー・方向・優先度）とフィルター状態（列ごとの選択値セット）を `schema/{テーブル名}.json` に保存し、テーブル再オープン時に復元する。現状はメモリ上のみで保持されており、タブを閉じると失われる。

## 背景

大規模テーブルでは特定の列でソートしたりフィルターを適用した状態で作業を続けることが多い。しかし現状はタブを閉じるかアプリケーションを再起動するとソート・フィルター状態がリセットされ、毎回再設定する必要がある。ISSUE_0133でフリーズペインの永続化をスキーマに保存する方針としたため、ソート・フィルターも同様にスキーマに保存して統一する。

## 要件

### ソート状態の保存

- `schema/{テーブル名}.json` に `sortKeys` フィールドを追加する
- 保存内容: ソートキーの配列（列名・方向・優先度順）
- 列名で保存する（列インデックスは列移動で変わるため）
- ソート未適用時はフィールドを省略する（既存スキーマとの互換性維持）

### フィルター状態の保存

- `schema/{テーブル名}.json` に `filters` フィールドを追加する
- 保存内容: 列名ごとの選択値配列
- フィルター未適用時はフィールドを省略する

### 保存タイミング

- ソート状態変更時（列ヘッダークリックでソート追加・変更・解除）に即座に保存する
- フィルター状態変更時（フィルタードロップダウンで適用・解除）に即座に保存する

### 復元タイミング

- テーブルをタブで開いた際にスキーマから読み込み、ソート・フィルターを適用する
- 復元時に存在しない列名が含まれていた場合（列が削除された等）は該当エントリを無視する

### スキーマJSON形式（追加分）

```json
{
  "header": ["id", "name", "hp", "atk"],
  "sortKeys": [
    { "columnName": "hp", "direction": "desc" },
    { "columnName": "name", "direction": "asc" }
  ],
  "filters": {
    "element": ["Fire", "Water"],
    "name": ["Slime", "Dragon"]
  }
}
```

### ミニテーブルでの扱い

- ミニテーブル（RelationsPanel内）ではソート・フィルター状態の保存・復元は不要（ミニテーブルは毎回動的に生成されるため）

## 期待される動作

### ソートの永続化

1. `enemy` テーブルの `hp` 列を降順でソートする
2. `enemy` タブを閉じる
3. `enemy` テーブルを再度開く
4. `hp` 列が降順ソートされた状態で表示され、ソートインジケーターも表示されている

### フィルターの永続化

1. `enemy` テーブルの `element` 列を「Fire」「Water」でフィルターする
2. `enemy` タブを閉じる
3. `enemy` テーブルを再度開く
4. `element` 列に「Fire」「Water」のフィルターが適用された状態で表示される

### 列削除後の復元

1. `enemy` テーブルの `element` 列にフィルターを適用して保存する
2. テーブル定義エディタで `element` 列を削除する
3. `enemy` テーブルを再度開く
4. 存在しない `element` のフィルターは無視され、エラーにならない

## 対象ファイル（変更）

- `WebView/src/column-sorter.ts` — ソート状態変更時にスキーマ保存を呼び出す、列名ベースのシリアライズ/デシリアライズ
- `WebView/src/column-filter.ts` — フィルター状態変更時にスキーマ保存を呼び出す、列名ベースのシリアライズ/デシリアライズ
- `WebView/src/editor-table.ts` — ソート・フィルター復元の呼び出し
- `WebView/src/tab.ts` — テーブルオープン時にスキーマからソート・フィルター状態を読み込み適用する
- `WebView/src/editor-actions.ts` — スキーマJSONへのソート・フィルター状態書き込み
- `WebView/e2e/freeze-pane.spec.ts` — ソート・フィルター永続化のテスト追加（またはspec新設）
