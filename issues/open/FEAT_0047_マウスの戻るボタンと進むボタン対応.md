# FEAT_0047 マウスの戻るボタンと進むボタン対応

## 概要

マウスのサイドボタン（戻る/進む）でアプリケーション内のナビゲーション履歴を操作できるようにする。

## 方針: ブラウザ History API（pushState / popState）を利用

独自の履歴管理ではなく、ブラウザ標準の History API を使う。

### 理由

- マウスサイドボタン（button 3/4）が WebView2 のデフォルト動作で自動的に動く
- Alt+Left / Alt+Right も自動的に動く
- C#側の対応が最小限で済む
- 新しい操作を追加するときは `pushState` を1行足すだけ（都度対応と相性が良い）

### 仕組み

```typescript
// 操作時に pushState で履歴を積む
history.pushState({ type: 'tab-switch', tabId: 'item' }, '');
history.pushState({ type: 'definition-jump', table: 'shop', row: 3 }, '');

// マウスサイドボタン or Alt+Left → 自動で popstate 発火
window.addEventListener('popstate', (e) => {
  const state = e.state;
  // state.type に応じて復元処理を分岐
});
```

## 対応予定の操作（都度追加）

- [ ] タブ遷移
- [ ] セルの選択座標
- [ ] テーブル、ミニテーブルを含むフォーカスを当てたテーブルの各種セルの選択
- [ ] 定義ジャンプ履歴
- [ ] フォームビューの深さ
- [ ] Relationsパネルの深さ
- [ ] REFERENCESパネルからのジャンプ 逆参照先を確認してジャンプした後、戻れないのは痛い

## 注意点

1. **初期ロードのエントリ保護**: pushState の履歴を全部戻りきると WebView2 の初期ロードエントリまで戻りページが消える可能性がある。初期ロード時に `history.replaceState` で初期状態をマークして防ぐ。
2. **C#側**: `NavigationStarting` で外部URLへのナビゲーションだけブロックする安全策を入れる。
