# ISSUE_0121 テーブル定義の作成・編集UIを追加する

## 概要

GUIでテーブルのスキーマ定義（列名・型・主キー・FK参照・動的参照等）を新規作成・編集できるUIを追加する。現状はスキーマJSONを手書きするか、既存テーブルの列挿入/削除で間接的に変更するしかない。専用の定義エディタを設けることで、非エンジニアでもテーブル設計を安全に行えるようにする。

## 背景

マスターデータの運用では以下の作業が頻繁に発生する:

- 新しいテーブル（新コンテンツ用）の作成
- 既存テーブルへの列追加（新パラメータ追加）
- 列の型変更（int → float 等）
- FK参照の設定・変更
- 主キーの変更

現状これらはすべてスキーマJSONファイルの直接編集が必要であり、JSON構文の知識がないプランナーには困難である。また、手編集によるJSON構文エラーやスキーマ不整合のリスクがある。

## 要件

### 起動方法

- **新規作成**: エクスプローラーパネルのヘッダーに「+」ボタンを配置する。クリックでテーブル定義エディタが空の状態で開く
- **既存テーブル編集**: テーブルタブのコンテキストメニューまたはツールバーに「テーブル定義を編集」を追加する。クリックで現在のスキーマを読み込んだ状態でエディタが開く

### テーブル定義エディタ（専用タブ）

テーブル定義エディタは専用のタブとして開く。タブ名は新規作成時「新しいテーブル」、既存編集時「{テーブル名} - 定義編集」とする。

#### テーブル基本情報セクション
- **テーブル名**: テキスト入力。新規作成時は必須入力、既存編集時は変更可能（リネーム）
- **説明（description）**: テキスト入力。エクスプローラーの2行目に表示されるテーブルの説明文

#### 列定義セクション（メインエリア）

列定義をグリッド形式で表示・編集する。各行が1列の定義であり、以下のフィールドを持つ:

| フィールド | 入力方式 | 説明 |
|---|---|---|
| 列名（name） | テキスト入力 | 英数字とアンダースコア |
| 型（type） | ドロップダウン | `string`, `int`, `float`, `double`, `bool` から選択 |
| 主キー（PK） | チェックボックス | ONの列が primary_key に含まれる。複合PK対応 |
| FK参照（reference） | 参照設定UI | 単純参照または動的参照を設定する（後述） |
| デフォルト値（default） | テキスト入力 | 任意。型に応じた値 |
| コメント（comment） | テキスト入力 | 列ヘッダーに表示される補足説明 |
| 列幅（width） | 数値入力 | ピクセル単位 |
| 並び順 | ドラッグハンドル | 行をドラッグして列の並び順を変更する |

#### 列操作
- **列追加**: グリッド末尾の「+ 列を追加」ボタンで空行を追加する
- **列削除**: 各行の右端に削除ボタン（x アイコン）を表示する
- **列の並び替え**: ドラッグ&ドロップで列の順序を変更する

#### FK参照の設定UI

列のFK参照フィールドをクリックすると、参照設定ポップアップが開く:

**単純参照の場合:**
- 参照先テーブル: ドロップダウン（既存テーブル一覧から選択）
- 参照先列: ドロップダウン（選択したテーブルの列一覧から選択）
- 結果: `テーブル名.列名` 形式の文字列としてスキーマに保存される

**動的参照（二段リスト）の場合:**
- 「動的参照を使用」チェックボックスをONにする
- sourceTable: ドロップダウン（中間テーブル選択）
- sourceMatchColumn: ドロップダウン（中間テーブルの列から選択）
- sourceMatchValue: テキスト入力（自テーブル内の参照元列名）
- destTable: ドロップダウン（中間テーブルの列から選択。参照先テーブル名が入っている列）
- destColumn: ドロップダウン（中間テーブルの列から選択。参照先列名が入っている列）
- 結果: `DynamicReferenceSchema` オブジェクトとしてスキーマに保存される

### バリデーション

定義保存時に以下を検証する:

- テーブル名が空でないこと
- テーブル名が既存テーブルと重複しないこと（新規作成時。リネーム時は旧名との一致は許容）
- テーブル名が英数字とアンダースコアのみで構成されること
- 列名が空でないこと
- 列名が同一テーブル内で重複しないこと
- 主キーが最低1列設定されていること
- FK参照先のテーブル・列が実在すること
- 型が有効な値であること

### 保存処理

- 「保存」ボタンクリックでスキーマJSONを生成・保存する
- **新規作成時**:
  - `schema/{テーブル名}.json` を新規作成する
  - `data/{テーブル名}.csv` をヘッダー行のみで新規作成する
  - エクスプローラーにテーブルを追加する
  - 保存後、テーブルをタブで開く
- **既存テーブル編集時**:
  - `schema/{テーブル名}.json` を上書き保存する
  - 列の追加・削除・リネームがあった場合、既存CSVデータの列を対応させる:
    - 列追加: CSVの全行に空セルを追加する
    - 列削除: CSVの該当列を除去する
    - 列リネーム: CSVヘッダーの列名を変更する
    - 列の並び替え: CSVの列順を新しい並びに合わせる
  - 変更後のCSVを `data/{テーブル名}.csv` に保存する
  - 開いているタブがあればテーブルを再読み込みする
- **テーブルリネーム時**:
  - 旧 `schema/` と `data/` のファイルを削除し、新名でファイルを作成する
  - 他テーブルからの FK 参照がある場合、警告を表示する（自動修正はしない）

### Undo/Redo

- テーブル定義エディタ内の操作（列追加・削除・値変更・並び替え）はエディタ内のHistory で Undo/Redo に対応する
- 保存操作自体は取り消せない（ファイルシステムへの書き込みは不可逆）

## 期待される動作

### 新規作成フロー
1. エクスプローラーの「+」ボタンをクリックする
2. テーブル定義エディタが新しいタブで開く
3. テーブル名に `enemy_skill` と入力する
4. 「+ 列を追加」で列を追加し、`id`（int, PK）、`enemy_id`（int, FK→enemy.id）、`skill_name`（string）、`damage`（int）を定義する
5. 「保存」をクリックする
6. `schema/enemy_skill.json` と `data/enemy_skill.csv` が作成される
7. エクスプローラーに `enemy_skill` が追加され、タブで開かれる

### 既存テーブル編集フロー
1. テーブルタブのコンテキストメニューから「テーブル定義を編集」を選択する
2. テーブル定義エディタが現在のスキーマを読み込んだ状態で開く
3. 新しい列 `critical_rate`（float）を追加する
4. 「保存」をクリックする
5. スキーマJSONが更新され、既存CSVの全行に `critical_rate` の空セルが追加される
6. テーブルが再読み込みされ、新しい列が表示される

## 備考

- C#側の修正は不要。ファイルの作成・削除は既存の `writeFileAsync()` / `deleteFileAsync()`（api.ts）で対応済み
- スキーマJSON の書き込みは `writeFileAsync('schema/{テーブル名}.json', ...)` で行う
- CSVの書き込みは `writeFileAsync('data/{テーブル名}.csv', ...)` で行う
- テーブルリネーム時のファイル削除は `deleteFileAsync()` で旧ファイルを除去する
