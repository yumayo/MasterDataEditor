# リレーションパネル編集機能 設計案

## 背景

現在リレーションパネルは参照先テーブルを「表示するだけ」で終わっている。
プロジェクトのゴールは「外部キーで参照しているIDを手打ちする苦痛の解消」であり、
リレーションパネルで直接編集・行追加ができなければこのゴールは達成できない。

## 現状の問題

1. リレーションパネルのテーブルは `makeReadOnly()` で編集不可
2. 参照先テーブルのデータを見ることしかできない
3. N:1 のデータを追加するには、タブを切り替えて手動で外部キーを入力する必要がある

## やりたいこと

### A. リレーションパネルのテーブルを編集可能にする

- `makeReadOnly()` を外す
- セル編集、Undo/Redo、ContextMenu をすべて有効にする
- 左ペインの EditorTable と同じ操作感で編集できる

### B. 行追加時に外部キーを自動埋め込みする

例: 「敵テーブル」で敵ID=3の行を選択中 → 右ペインの「ドロップアイテムテーブル」で行追加
→ 新しい行の `enemy_id` カラムに `3` が自動で入る

これにより「IDを手打ちする苦痛」が解消される。

### C. 右ペインの編集を左ペインに即時反映する

右ペインで参照先の名前等を変更した場合、左ペインのJOIN表示にも即座に反映する。

## フォーカス管理

左ペインと右ペインの両方に EditorTable がある。
既にフォーカス排他制御が導入済みなので、クリックしたテーブルにフォーカスが移る仕組みをそのまま活用する。

## 未決事項

- 右ペインで行削除した場合、左ペインの外部キー参照はどうなるか？
A. すべて削除された場合、リレーションを切ってください。

- 右ペインの Undo/Redo は左ペインと独立か、統合か？
提案: テーブルごとに独立で良いと考えます。
各 EditorTable が自分のストアに対する CommandHistory を持っているはずなので、
そのまま自然に独立になります。統合すると「どのテーブルの操作を戻すのか」が曖昧になり複雑化します。
A. OKではテーブルごとに独立としましょう。

- リレーションパネルでのドリルダウン先テーブルも編集可能にするか？
提案: はい、すべて編集可能にすべきと考えます。
ドリルダウン先だけ readOnly にする理由がありません。
「どの階層でも編集できる」のほうがシンプルで一貫性があります。
Q. ドリルダウン先テーブルというのは実装されてるんですか？
A. ロジック（drillDownAsync）は実装済みだが、発火するUIイベントが未接続。
clickだとdblclick（セル編集）と競合するため、意図的に無効化されたまま放置されている。
→ 今回の編集可能化で、ドリルダウンの発火UIも合わせて検討する必要がある。

## D. ドリルダウン = 左ペインで開く（定義へジャンプ）

### 設計方針
ドリルダウンは右ペイン内で階層を深くするのではなく、左ペインのタブとして開く。
常に「左ペイン = メインテーブル、右ペイン = その関連テーブル」の2ペイン構造を維持する。
これにより右ペインに無限に階層が増えることがなく、シンプルさが保たれる。

### 操作
- Ctrl+クリック、またはセル選択状態で F12（VSCodeの「定義へ移動」と同じ操作感）
- 参照先テーブルの該当行にフォーカスした状態で左ペインにタブが開く
- 右ペインは新しいタブのリレーションに自動更新される

### パンくずリスト（タブ遷移履歴）
ドリルダウンの遷移履歴をパンくずリストで表示する。
例: イベント → クエスト → エネミー → レベルデザイン → スキル
パンくずのクリックで任意の地点に戻れる。戻った後に別方向に進める。
例: イベント → ガチャ（スキルの先にいたが、イベントまで戻ってガチャへ）

### 現行の navStack / drillDownAsync について
右ペイン内の階層管理（navStack、パンくずリスト）は廃止し、
タブ遷移履歴としてパンくずリストを再設計する。

### 外部キー列の表示
リレーションパネルでは外部キー列を非表示にする。
ただし、テーブルヘッダーに「quest_id=3 でフィルタ中」のようなコンテキスト表示を出す。
理由: 複数の親テーブルから参照されるテーブルの場合、どの文脈で表示されているかわからなくなるため。

## E. 左右ペインの認知支援

### 編集中テーブルの視覚的区別
左右どちらのテーブルを編集しているかをユーザーが常に認識できるようにする。
右ペインのテーブルには背景色やボーダーで視覚的に区別をつける。
（フォーカス排他制御に加え、静的な視覚差も設ける）

### 未保存インジケータ
右ペインで編集した変更が未保存の場合、テーブル名の横にドット等のインジケータを表示する。
テーブルごとにUndoが独立しているため、「どのテーブルに未保存の変更があるか」を明示する。

## F. 左ペイン変更時の右ペイン追従

左ペインで外部キーの値を変更した場合、右ペインのフィルタリングも追従する。
例: quest_id=3の行を選択中に左ペインでそのidを5に書き換えたら、
右ペインはquest_id=5に紐づくリレーションに切り替わる。

### プランナー要望
- 自動埋め込みされた外部キーセルのロック
- 右ペインのテーブルを左ペインのタブで開くボタン

- 一括置換（Ctrl+H）
- 行の並べ替え（ドラッグ or Alt+上下）
- 差分プレビュー（保存前の変更確認）

- 列のフィルタ・ソート
- 条件付き書式（セルの色分け）
- 編集ロック（列単位）
- テンプレート行
- 編集履歴の可視化
- セルコメント/メモ
- マルチカーソル編集

- 複合外部キーへの対応
- 右ペインのソート・フィルタのカスタマイズ
- 一括編集（複数行選択 → 同一列の値を一括変更）
